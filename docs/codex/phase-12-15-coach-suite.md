# Phases 12–15 · 教练工作台

升级基线为 Phase 11 提交 `60e042a`。保持 7.42 的 24 手 CM 顺序、历史存档顺序、修订号检查和本地离线推荐。五个一级工作区共用固定顶栏，桌面导航和移动底栏使用同一份路由配置。

## 从赛前准备到赛后复盘

| 场景 | 操作与结果 |
| --- | --- |
| 对手关闭路人战绩 | 在选手设置批量粘贴 Steam32、Steam64 或 OpenDota、Dotabuff、Stratz 主页。填队内代号和位置，为英雄标记招牌、常用或避坑。两榜与战队侦察可直接使用这些标注。 |
| 准备战队名单 | 在战队浮层中搜索选手或新建并绑定。选择已在阵中的人会交换两个槽位，也支持首发与替补互换。保存后查看优先禁用、多人摇摆和各位置厚度。 |
| 现场决策 | 从空白盘面进入，或带一侧战队开局。点英雄进入预选，阵容诊断切到相应一方。推荐第 4–10 名点行即可看完整拆解。只有显式确认或确认快捷键推进禁选。 |
| 修正现场录入 | 点击已锁槽，选择替换英雄，再确认。修改位置或选手可独立进行。敌方已选槽支持直接钉住预测位置，也可手动改为其他开放位置。 |
| 核对赛后数据 | 比赛导入先显示去重编号，再按标签入库。十人计分板保留空装备格、中立装备、正反补、治疗量、英雄和建筑伤害。建队复用公开账号，以主位置、英雄定位和分路共同匹配五个槽位，匿名账号的位置留空。 |
| 按选手复盘 | 默认汇总该选手已解析场次。阵营和所玩英雄条件同时作用于视野与刷钱。点击单场可展开十人出装。路人摘要可按需读取单场详情，保留路人来源。 |

## 推荐依据

选人考察我方未分配首发，禁人考察敌方未分配首发。`assignedPlayerId` 和明确的 `roleHint` 都能排除已经出英雄的目标。只选战队但没有战绩或标签时，该侧继续使用自由模式。

| 因素 | 自由模式前中期 | 自由模式第 16 手起 |
| --- | ---: | ---: |
| 克制、反制机制与对位样本 | 40% | 45% |
| 六维缺口、位置与双人配合 | 36% | 35% |
| 版本基线 | 20% | 16% |
| CM 轮次策略 | 4% | 4% |
| 个人英雄池 | 0% | 0% |

战队模式中，选人的个人英雄池占 60%，目标禁人的个人威胁占 62%。其余因素按上表比例分配剩余权重。58 组机制关系提供可读依据。选手比赛和路人样本区分版本、阵营与位置；相同赛事与路人记录只计一次。手动招牌可以开启绝活门槛，常用提高熟练度，避坑压低个人贡献。每条建议的 `scoreBreakdown` 按实际贡献分展示。高操作与低登场英雄的有效样本要求继续适用。

阵容诊断并排显示双方六维数值。预选条给出定位和阵容增量，原位替换按被改动的手数重算。三段发力窗口根据当前英雄的控制与爆发、团战与推进、持续输出与前排给出教练提示。BP 赢面和窗口强度均为阵容估算。

## 数据口径与兼容

- **战队阵营胜率**按至少三名当前首发同场同边的赛事去重。BP 情报卡仍按当前选手在相应阵营的样本统计，界面分别标出场次与人次。
- **眼位存活**优先用实体句柄匹配放置与移除。无句柄时使用相同坐标和非负时间差，一次移除只使用一次。缺少移除事件时保留原落点字段；有移除时间而无攻击来源时标为原因未知。
- **刷钱区域**在每名选手自己的阵营视角分类，再汇总权重。安全线、施压线、中路河道、己方主野区、三角区与远古、敌方野区均为小地图近似分区。占比来自位置采样次数。
- **Schema v8**新增选手档案、复合主键英雄覆盖表，以及反补、治疗、中立装备与两类守卫移除日志。迁移在事务中进行，重复启动不会覆盖已有记录。
- **JSON 备份**导出 v5，可恢复 v2–v5。旧快照缺少的覆盖记录为空，新增列按默认值补齐。恢复事务受外键与字段校验约束。OpenDota API Key 保留在当前服务。
- **浏览器配置**使用 `bp-setup-v5`。首次进入会清理旧版可能自动装队的配置。手动保存的 v5 阵容可复用，动作跨刷新通过存档恢复。Service Worker 资源壳使用 `v10-__BUILD_ID__`。

## 界面与验证

顶栏采用固定高度和等高占位，BP 操作集中在页内工具条。折射仅作为背景层合成，文字独立绘制。导航岛和浮层保留三通道位移，镜面光权重为 0.09。小胶囊使用缎面渐变，推荐卡使用均匀细描边。已锁肖像用去色、压暗、阵营色和文字共同识别。

在仓库根目录使用 Node.js 24 和 npm 11 运行：

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
```

`test:browser` 使用构建产物、独立的内存数据库、本地随机端口和临时浏览器上下文。Windows 默认使用已安装的 Edge，其他 Chromium 路径通过 `BP_BROWSER_PATH` 指定。像素检查直接读取内存截图。

| 验收项 | 检查方法 |
| --- | --- |
| 空白开局与已有战队隔离 | 内存库预建战队，核对初始双边阵容、127 个英雄及四属性数量。 |
| 防误锁 | 浏览器逐行展开第 4–10 名、双击推荐和肖像、点击独立确认、原位替换，再核对已落手数。手机浮层重复验证。 |
| 导航与首屏 | 比较五页实际渲染后顶栏、导航岛及五个链接的四个矩形分量。滚动超过 400px 核对顶栏 y。1920×1080 检查整个四宫格底边和分栏间隙截图像素。 |
| 小屏复盘 | 375×812 检查五页与展开后的十人计分板宽度，核对 10 行、70 个装备格及导入编号预览。 |
| 数据回归 | 运行 v7→v8 与重复迁移、旧备份恢复、批量账号、标签 CRUD、两榜独立权重、位置钉选、提取建队、两种热图英雄筛选、眼位时长及战术区域测试。 |

本次验收使用 Edge 无头浏览器。1920×1080 下，四组英雄池底边为 1020.89px，岩板间隙采样为 RGB(30, 44, 60)，五页顶栏、导航岛与全部标签的矩形偏移均为 0px。375×812 下五页与展开后的十人计分板均无横向溢出。桌面使用正常动效，小屏复测启用减少动态效果。91 项 Node 测试通过，另有独立浏览器验收。

OpenDota 请求和录像解析使用控制样本验收。对真实账号的公开性、接口额度或录像是否仍可解析，取决于实际联网同步结果。
