## 推荐计算

1. **版本强度。** 将高分局胜率向五成收缩，再结合职业 BP 率和高分局选取率，分别占版本评分的 48%、37%、15%。按全英雄评分排名划分 T0、T1、T2、T3，分界为前 8%、30%、68%。分级是本应用的模型结果。
2. **阵容补足。** 双方各自先保留手动位置和已绑定选手的分工，对其余英雄匹配 1–5 号位，优先覆盖更多不同位置，再优先常见分路。先手硬控、前排承伤、爆发伤害、持续输出、推进拆塔、团战反手各记 0–100 分。将候选英雄加入对应阵容重新求解，得到实数增量、新覆盖位置、物理／魔法／纯粹伤害结构及近远程人数。伤害比例来自英雄职责估计。
3. **克制与协同。** 离线可用本版职业赛交手样本和内置技能配合。手动同步已选英雄对位后，优先使用本地 hero_matchups 的 OpenDota 样本，支持反向胜负换算。对位说明列出场数和相对英雄高分局基线的胜率差，计分时按样本量收缩。经典配合列出双方技能关系，机制判断的 deltaPct 为 null。

空阵容开局给版本强度 54%、阵容 21%、对位协同 17%、顺位策略 8%。亮出本方英雄后，阵容权重升至 38%。末轮提高针对权重，考虑后选方末手奇招。分阵营职业胜负样本经平滑后进入策略分。每一方的选手权重独立计算。没有可用英雄池时为零，少量样本时按场数渐进加权，样本充分时占约 34%–42%，其余因素同比例缩减。赛事权重及路人局近期／生涯统计沿用选手分析设置，已占用的选手从候选池移出。多人均熟练的招牌英雄额外提高针对禁用优先级。

选人和禁用各返回前十名。前三张卡展示版本、补位或禁用动机、对位与协同，以及有记录时的选手战绩。禁用动机分为版本强势、保护核心、拆解体系、末手奇招和选手绝活。推荐分是排序分值。选取率、胜率和职业争夺率各自带有明确的数据口径。

## 对局室操作

- 首页直接进入对局室。双方各显示 5 张选人卡、7 个按轮次分组的禁用槽。时间线标示当前手、禁选类型、阵营及连续操作提醒。战队与选手配置默认收起。
- 实战顺序用 F 表示先选队、S 表示后选队。从首至末为禁 FFSSFSS、选 FS、禁 FFS、选 SFFSSF、禁 FSFS、选 FS。对照了补丁 ID 61 的四场职业赛。升级时保留已有禁选进度的历史顺序。[实战禁选记录](https://api.opendota.com/api/matches/9104260611)
- 英雄池按四属性固定分组。中文、别名、英文、拼音首字母和位置可以叠加筛选，未命中的卡片原地变暗。已选与已禁英雄均不能再次录入。
- 单击预选时可查看六维变化。禁用预览显示被拦截一方若拿到英雄能补强什么。Enter 确认，双击或开启「单击直锁」可直接执行当前手。斜杠聚焦搜索，Ctrl+Z 撤销，Ctrl+Shift+Z 重做，Esc 取消预选或收起配置。已选卡支持更改位置和绑定选手。
- 推荐视角固定为我方选人或针对对方禁用。可切换查看后续计划，锁入按钮同时显示实际生效的阵营视角和动作。有对手阵容时，情报页保留通往眼位及核心打钱热图的入口。
- 手机使用四个属性跳转按钮，候选确认条在底部导航上方。对局存档可跨设备载入，浏览器本机草稿会自动恢复。

## 5b · 按选手复盘

进入「录像分析」会选中一名选手，并显示「全部已解析比赛聚合」。可以按昵称搜索，也可以点战队查看首发和替补。卡片标明偏好位置和已解析场数。聚合只统计这名选手亲自参加的已解析赛事。

参赛记录按开赛时间倒序排列。通过英雄肖像、中文名、阵营、胜负、击杀／死亡／助攻、赛事和日期辨认比赛。点记录会将地图与统计一起切换到该选手当场的样本，点聚合按钮即可返回。待解析场次可在记录旁请求解析，完成后自动更新场数和热图。

眼位支持按阵营、真假眼和比赛时段筛选。刷钱图展示位置采样密度与区域占比，可以查看全部位置或仅核心位。OpenDota 的位置网格没有时间戳，因此无法重建逐分钟的移动顺序。

比赛库的「查看热力图」打开当场十人名单，优先选中已关联的选手，无人关联时选中第一位。可直接切换两方参赛者，未入库的账号和匿名选手也能单独查看当场数据。对局室的选手槽可以直达个人录像，对手情报卡的眼位入口优先选择辅助，核心刷钱入口优先选择核心，并带入当前阵营。

接口字段、各层筛选条件及空样本的统计口径见[录像分析 API](api.md#录像分析)。

## 验收

`server/test/phase5.test.ts` 从 HTTP 入口覆盖离线首启、版本与属性、物品词典、零选手双榜、缺先手与前排时的分数变化、分阵营预览、选手自适应权重和同步失败回滚。其余测试继续覆盖备份恢复、位置分配、反向对位、录像和比赛导入。本次 `npm run typecheck`、`npm test`（52 项）和 `npm run build` 全部以退出码 0 完成。真实联网调用 `POST /api/constants/sync` 返回 HTTP 200，SQLite 完整性和外键检查通过。

在 1440px 和 375px 的无头 Edge 中逐张检查了英雄池图片解码，逐个比较搜索和位置筛选前后的卡片位置，并测量页面宽度。两种视口均无横向溢出。验证了预选、回车、双击、单击直锁、撤销重做、推荐切换和配置收起。另在已有赛事的十人记分板上核对全部 60 个装备槽，其中 58 格显示本地图标，并验证中文悬停名称。

5b 验收使用 Node 24 内置 SQLite。`npm run typecheck`、`npm test`（54 项）和 `npm run build` 均以退出码 0 完成。在构建产物上使用内存赛事库和模拟的 OpenDota 解析任务，验证了按首发和替补筛选、个人聚合与单场统计、十名参赛者逐人切换、匿名槽位、解析后自动刷新，以及 BP 选手槽和两个对手情报入口。1440px 与 375px 视口均核对了页面宽度、控件宽度和英雄肖像解码，包含长昵称样本，未发现横向溢出。
