# 第六阶段 · 队长模式 BP 分析

## 版本样本

OpenDota 的 7.42 条目为 ID `61`、发布时间 `2026-11-18T21:28:07.019Z`。与逐场数据对齐后，起算时间为 Unix 秒 `1795037287`。启动可直接使用内置边界。同步版本常量时，服务同时保存这条边界及从 7.42 起的全部已知补丁 ID。[OpenDota 版本原表](https://api.opendota.com/api/constants/patch)

Schema v5 在事务内给 `player_pub_matches` 增加可空的 `patch`，给 `player_pub_heroes` 增加初值为零的 `patch_games`、`patch_wins`。升级、同步和旧备份恢复时，服务按官方补丁日历给缺少版本的逐场记录回填 ID。离线快照覆盖 7.41、7.42 至快照时间，同步常量会扩展为完整日历。超出核实区间时保留空值，评分仍可按 7.42 起算秒筛选。明确的补丁 ID 或版本名优先。旧生涯行的最后使用时间只能说明最近玩过，无法证明整行场次都发生在新版。

同步选手时，服务读取生涯明细、最近 50 场的字段投影，以及各个已知补丁的 `/players/{account_id}/heroes?patch={id}`。OpenDota 的 patch 条件是等值筛选。服务把各版汇总相加，再与同版逐场记录的已知胜负下限合并。能按比赛 ID 识别的赛事重合记录只计一次。英雄汇总缺少可供逐条核对的比赛 ID，其阵营拆分只展示已知逐场记录。

近况、站边胜率、分路和搭档组合使用版本内记录。选手卡保留生涯场次供查阅。赛事倍数默认 4，生效范围 0–8；路人窗口默认 60 天。当前版本路人窗口内逐场为一倍，其余版本内路人场为 0.75 倍。胜率向五成收缩，出场量和近期使用情况共同决定熟练分。旧记录按 0.15 折算，最多三分；每积累一场本版样本，这项加分再减少五分之一，满五场后退出评分。

## 当前手的取舍

| 手数 | 选人或禁用优先级 |
| --- | --- |
| 1–7 | 先封职业赛争夺率高的版本英雄、强势摇摆点，再考虑对手打得好的本版英雄。 |
| 8–9 | 抢四、五号位，允许强势的三号位摇摆。纯一、二号位留在后手。 |
| 10–12、19–22 | 查看敌方已亮分工，封锁其空位。敌方只缺一号位时，榜单全部具备一号位能力。 |
| 13–15 | 先看未满双辅和三号位，双辅齐全后转向三号位。 |
| 16–18、23–24 | 先补尚缺的一、二、三号位，把对位占大数据部分的比例提高至 33%。核心齐全时回补实际空位。 |

手动选位立即作用于我方选人和针对敌方的禁用榜。明确指定单一位置时即使该位已有人，也可查看对应英雄。英雄池加分只给能补空位、版本表现达到 T2 及以上的英雄。已分配英雄的选手退出候选，剩余选手按本场槽位与英雄常见位置匹配。

有选手记录时，默认 82% 来自版本、阵容、对位和顺位策略，18% 来自选手熟练度。选手权重可在 15%–20% 间调整。没有英雄池数据的一侧把全部权重分给大数据。版本强度综合高分局胜率、选取率及职业赛争夺率。对位采用本版职业赛样本，对同步所得的跨版对位最多折算八场作为先验；缺少职业赛对位时使用同步样本。已知技能克制、机制标签和队友连招独立进入对位分析。

## 阵容、对线和胜率

固定位置与已分配选手优先，其余英雄在常见位置中寻找覆盖最多的分工。诊断结合输出类型、近远程、先手、救人、探坡、拆塔、控盾和线上压力。以幻影刺客、兽王、祈求者、帕吉为例，兽王能先手探路，但阵容仍缺救援，且三名近战容易被拉扯。敌方破阵页按已亮阵容寻找突破口，例如冰魂封治疗、范围技能清幻象、点控抓机动核。候选须具备对应机制，优先匹配我方空位和版本强度。

HUD 将版本、对位、阵容、阵营四项差值换算为天辉视角的百分点。双方亮人较少时前三项收缩，空局从天辉 50.4% 起步，天辉最终估值限制在 30%–70%，夜魇取补数。它是基于 BP 的启发式估算，尚未用留出赛事做胜率校准。

双方各亮两人后开始推演三路。一、五号位对敌方三、四号位，二号位单独对线。强线标签、近远程组合和英雄对位决定「强优」至「劣势」的五档判断。单边无人时显示「待亮人」，边路只亮一人时显示「分路待定」。上下路随天辉、夜魇互换。

## 迁移和验收

- 服务使用 Node 24 自带的 `node:sqlite`。启动即执行幂等迁移。全员补拉可调用 `POST /api/players/resync-patch`，也可继续使用原有的个人、战队同步入口。批量结果逐人返回。
- 本次升级前保留了工作区内的 SQLite 快照。实库 19 名选手全部完成同步，18 人有版本路人汇总，共 346 场、176 胜。按选手计的 954 条逐场记录全部匹配到补丁，其中 608 条属于 7.41、346 条属于 7.42。迁移前后的选手身份、队伍、成员、比赛和原路人记录主键均已核对，完整性及外键检查通过。
- `server/test/phase6.test.ts` 覆盖旧库升级、跨补丁汇总、边界秒、旧绝活降权、选手预算、选人禁用阶段、手动倾向、机制补强、分路映射和估值边界。标准检查为 `npm run typecheck`、`npm test` 和 `npm run build`。
- 无头 Edge 在本机 3006 端口的生产构建上使用两支实库队伍和专用浏览器草稿，分别在 1440px 和 375px 下验证三张决策卡、七行候选、选位重排、胜率条、分路、补强预选和破阵直锁。浏览器实测页面宽度等于视口宽度。测试草稿只保存在验收浏览器内。

请求示例与响应字段见 [API 文档](api.md)。
