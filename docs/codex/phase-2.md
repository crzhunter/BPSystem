# 第二阶段 · 赛事战绩与 BP 备战

默认入口仍是「实时 BP 对局室」。队长可以在分配位置时看到该选手最常用的高分英雄、比赛和路人的胜率，以及当前阵营的历史胜率。客户端复用一期同源 API、侧栏、移动底栏和本机备战阵容。

## 数据库升级

Node 24 内置 `node:sqlite` 的 `DatabaseSync` 执行版本 2。每次启动只执行缺失的迁移，DDL 和版本记录在同一事务中提交。已经保存的选手、阵容、赛事和分析参数继续生效。未配置的赛事权重取 4.0，近期窗口取 60 天，显式设置的零权重有效。

| 表 | 二期用途 |
| --- | --- |
| `player_pub_heroes` | 主键为选手和英雄 ID。保存 OpenDota 生涯场次、胜场、最近使用时间、同队及对阵的场次与胜场，以及同步时间。 |
| `player_pub_matches` | 主键为选手和比赛 ID。保存槽位、实际阵营、个人胜负、开始时间、时长、击杀／死亡／助攻、每分钟金钱与经验、分路、模式、大厅类型和组队人数。选手删除时级联清理。 |
| `matches` | 复用赛事来源、标签、版本、时间、胜方和解析状态，新增双方队名。 |
| `match_players` | 复用槽位、阵营、账号、英雄、经济、装备、选取顺序及录像字段，新增昵称、英雄伤害、建筑伤害和正补。按账号和比赛建立索引。 |
| `match_picks_bans` | 按原始顺序保存禁选动作、英雄和实际阵营。首个选人动作的阵营为先选队，缺少选人记录时先选标志为 NULL。 |

OpenDota 开始时间使用 Unix 秒，时长为秒，业务创建及同步时间使用 UTC ISO 字符串。玩家槽位小于 128 为天辉，个人胜利取决于实际阵营与胜方是否一致。匿名参赛者仍占据记分板中的位置。比赛导入后，查询按账号关联选手库，新增选手会立即关联此前导入的比赛。换绑选手账号会清除旧账号的路人记录、头像和同步状态，赛事关联随新账号重新计算。

## 同步和导入

选手同步依次请求 OpenDota 的 `/players/{account_id}`、`/heroes` 和 `/matches?limit=50`（后两者相对于选手路径）。逐场请求显式投影英雄、时间、KDA、经济、分路、组队与联赛字段。逐场接口不可用时尝试 `/recentMatches`。上游明确标记联赛的记录跳过路人逐场入库。各入口共用一期的滑动窗口限流、同请求合并和默认一小时 SQLite 缓存。

有数据时替换生涯快照；逐场按主键更新并保留早期同步得到的比赛。一次成功同步内，缺少个人资料或同时没有已玩英雄及比赛样本时，会标记「未公开路人战绩」。未同步时隐私状态保持初始值，可通过空的 `lastSyncedAt` 区分。未公开时保留此前已采集的战绩。上游连接失败、密钥拒绝或格式错误会返回错误。资料和战绩在同一事务写入。

比赛库接受比赛 ID，以及 OpenDota、Dotabuff 的比赛链接，支持用空白、逗号或分号分隔。先去重，再逐场抓取和提交；同场重导更新整份记分板与禁选，省略标签时保留原标签。每场验证双方各五个唯一槽位。选人次序优先使用上游字段，否则从禁选记录推导：`draft_order` 沿用原始动作序号，`pick_order` 只计选人，从 1 开始。上游标记已解析，或存在实际眼位、分路坐标数据时，详情显示「已解析录像」。

## 分析口径

- 近期状态取本地时间最新的 20 场路人逐场记录。KDA 是各局 `(击杀 + 助攻) / max(1, 死亡)` 的平均值。每分钟经济和经验分别对已知值求平均。连胜或连败从最新一局向前计算，直到结果改变或用完已保存样本。
- 阵营胜率来自有胜负信息的逐场记录。分别返回比赛、路人和综合三组结果，每组给出天辉／夜魇的场次、胜场、胜率，以及天辉减夜魇的百分点差。空样本的胜率和不可计算的差值返回 `null`，前端显示「—」。生涯汇总没有阵营字段。
- 已导入赛事与路人记录的比赛 ID 重合时，逐场仅计赛事，并从路人生涯汇总扣除已知重合样本。路人生涯总胜、总负分别取校正汇总与已保存逐场统计的较大值。OpenDota 生涯汇总不含逐局 ID，超出已保存逐场历史的重合无法精确识别。
- 位置根据本方视角的分路和英雄职责推断。中路归 2 号位。优势路归 1 号位，偏辅助的英雄归 5 号位。劣势路对应 3／4 号位。辅助倾向指职责含 Support 且不含 Carry。未知分路和野区记录跳过，百分比的分母为可推断的局数。

### 英雄评分

对每个英雄，`T` 为比赛场次，`P` 为路人总场次，`R` 为近期窗口内的路人逐场场次。相应的胜场用下标 w 表示。比赛权重 `k` 和窗口天数取当前系统设置。

```text
有效场次 G = k × T + R + 0.15 × (P − R)
有效胜场 W = k × Tw + Rw + 0.15 × (Pw − Rw)
平滑胜率 B = (W + 2) / (G + 4)
出场因子 E = G / (G + 8)
活跃度 A = clamp(1 − 距最近出场天数 / 窗口天数, 0, 1)
评分 = 100 × (0.55 × B + 0.35 × E + 0.10 × A)
```

先验相当于 2 胜 2 负，避免小样本的 100% 胜率主导排序。未计入近期逐场的生涯样本给予 0.15 倍权重。赛事权重为零时赛事时间也退出活跃度计算。有效场次为零时得零分。评分保留两位小数，`weightedScore` 和 `threatScore` 返回同一数值。70 分起为 S，50 分起为 A，其余为 B。英雄池同时返回分来源的原始胜率、样本量、最近使用时间和实际阵营计数，来源标记为「比赛局」「路人局」或「双源融合」。

## HTTP 接口

以下路径以 `/api` 开头。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /players/:id/sync` | 返回更新后的 `player` 和 `analytics`，其中 id 是本地选手 ID。 |
| `POST /teams/:id/sync` | 首发和替补按槽位顺序同步，`results` 包含每位选手的成功、隐私状态或错误。 |
| `GET /players/:id/analytics` | 返回 `isProfilePrivate`、`privacyHint`、`lastSyncedAt`、`recentForm`、`roleDistribution`、`sideSplits`、`heroPool`。 |
| `POST /matches/import` | 请求示例为 `{"matchIds":[9104260611,"https://www.opendota.com/matches/9104260611"],"tag":"秋季杯"}`。返回逐场 `imported`／`updated`、`hasParsed`、`linkedPlayersCount` 或 `error`。 |
| `GET /matches?tag=&q=` | 标签精确匹配，搜索支持 ID、队名、选手账号或昵称、标签。列表包含双方名称、人数、胜方、时长、录像状态、关联数量和禁选预览。 |
| `GET /matches/:matchId` | 返回比赛摘要、按槽位排列的十人数据、选手库关联、完整禁选时间线和守卫计数。 |
| `DELETE /matches/:matchId` | 删除该场赛事及参赛者、禁选记录，成功返回 204。 |
| `POST /players` | 记分板复用一期创建入口，用参赛者账号加入选手库。 |
| `GET /system/network` | 移除回环、169.254/16、198.18/15 和 IPv6。RFC1918 地址排在其他 IPv4 前面。 |
| `GET /backup/export` | 下载版本 2 的 JSON 快照，含导出时间和各业务表数组。 |
| `POST /backup/import` | 请求体为导出的完整快照。验证版本、表、字段类型、JSON 结构、设置值和关联约束，事务成功后返回各表 `counts`。单次请求上限 64 MiB。 |

备份包含分析参数、英雄、选手、战队及成员、赛事及子表、路人汇总与逐场记录，以及数据库中的备战会话、动作和英雄对位。恢复采用**整库业务数据替换**，保留主键与本机 OpenDota 密钥，清理可重建的请求缓存。任一表校验或写入失败，全事务回滚。浏览器当前阵容保存在 localStorage，独立于服务器备份。

## 页面与验收

1. **比赛库 / 导入**可粘贴一组比赛并设置标签。查看逐场导入结果，展开记分板查看双方五人、完整禁选和眼位数量。有账号的参赛者可以直接加入选手库。
2. **选手库、战队管理**分别提供个人和全队同步。展开选手即可查看分来源的绝活池、阵营胜率、近期表现、位置倾向和隐私提示。
3. **实时 BP 对局室**支持手选和战队填充。每个已填槽位按当前阵营展示胜率，列出评分最高的三个英雄及「赛／路」胜率。交换阵营会切换对应侧的数据。「同步本场双方数据」只处理当前上场的已保存选手。
4. **系统设置**可以保存分析参数、下载 JSON 和选择文件恢复。执行替换前会提示覆盖范围。

自动化验证使用 `npm run typecheck`、`npm test`、`npm run build`。二期回归位于 `server/test/phase2.test.ts`，使用内存数据库、HTTP 服务和可控 OpenDota 响应。另以真实 OpenDota 比赛 9104260611 进行桌面及移动浏览器联调，在 Edge 的 375px 视口实测五页，包含展开的十人记分板、选手卡及有数据的 BP 槽位。
